# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MALT ("Multi-Agent Local Team") is a VS Code extension, MIT-licensed and open source (public repo `Division4Studios/multi-agent-local-team`). Its purpose is to help teams get AI-assisted PRs merged faster and more safely, by reviewing every changed block surgically as it appears instead of reviewing a huge PR at the end. Don't invent features beyond what the user has described.

This repo must model the anti-slop bar it will enforce elsewhere. Keep diffs small, don't add speculative abstractions, and don't leave unused code.

## Commands

```sh
npm ci                 # install (install scripts are disabled by .npmrc)
npm run verify         # check-deps → check-types → lint → test (what CI runs, minus audit)
npm run compile        # TypeScript 7 in Docker → out/
npm run check-types    # extension (tsconfig.json) + scripts (scripts/tsconfig.json)
npm run lint           # ESLint, --max-warnings 0
npm run check-deps     # dependency allowlist / exact-pin / reviewed-security-overrides guard
npm run audit          # whole tree (low+) + registry signatures
npm test               # compile, then run tests in a downloaded VS Code (.vscode-test/)
npm run vsix           # package .vsix
npm run release:bump -- minor   # next version in package.json/lock + dated CHANGELOG section (docs/releasing.md)
npm run test:live      # real Claude calls of every kind against the Docker reviewer (needs ANTHROPIC_API_KEY or CLAUDE_CODE_OAUTH_TOKEN)
```

There is no single-test filter. To run a subset, temporarily narrow the file list in `src/test/suite/index.ts`, or put the cases in their own `*.test.ts` file.

## Hard rules (user-mandated)

- **Dependencies are frozen.** The only allowed devDependencies are `@typescript/native` (exact alias to TypeScript 7), `typescript` (exact alias to Microsoft's TypeScript 6 compatibility package), `@types/node`, `@types/vscode`, `eslint`, `@eslint/js`, `typescript-eslint`, `@vscode/test-electron` and `@vscode/vsce`. **Zero runtime `dependencies`.** No mocha, esbuild, prettier or anything else. `scripts/check-deps.mts` enforces this. Never add a package without the user's explicit approval.
- **No unreviewed overrides or resolutions.** The user approved only the exact parent-scoped minimatch overrides documented in `SECURITY.md`. Preserve that guard and the low-severity audit gate.
- **Exact version pins only** (`.npmrc` has `save-exact`).
- **Lint: every rule is an error, and `eslint-disable` comments don't work** (`noInlineConfig`). Fix the code; never weaken `eslint.config.mjs` unless the user asks. The config bans `as` assertions, `!`, `any`, `@ts-*` directives, constructor parameter properties (via `erasableSyntaxOnly`), `console` in `src/`, `child_process`/`vm`/`eval`, TODO comments, and imports of `minimatch`/`glob`. It also enforces explicit return types and complexity/size limits.
- **The only naming exception** is the type property `HEAD` in `src/git/gitApi.ts`, which mirrors VS Code's Git API.
- **Extension process execution is allowed in exactly two files:** `src/backend/hostBackend.ts` and `src/reviewer/providers/claudeCode.ts`. The development-only `scripts/compiler.mts` also has a reviewed exception to launch Docker without shell interpolation. These exceptions are in `eslint.config.mjs`. The extension never runs git or docker itself; it uses the built-in Git extension API and the Docker Engine API over `node:http`.

## Feature architecture

Data flows: **git change → blocks → review queue → reviewer service → decorations/hover/sidebar.**

- **Change tracking** (`src/review/changeTracker.ts`) subscribes to the built-in Git extension's repository state (`src/git/gitApi.ts` types only the subset used), so agent edits on disk are picked up. Each changed file is diffed with `diffWithHEAD` (cached per file; the cache key includes `state.HEAD.commit`, so commits and checkouts invalidate it) and split by `src/diff/unifiedDiff.ts`: one block per git hunk; untracked files are split at blank lines into blocks of 30–80 lines. A block's id is a hash of path plus body (no line numbers), so cached reviews survive line shifts. Results persist in `workspaceState`.
- **HunkStore → ReviewQueue** (`src/review/`): each block gets one overview call (`POST /review`: summary, business purpose, technical, design, and the ids of applicable rules), then one isolated call per applicable rule (`POST /check`). Concurrency is bounded per call, and a started block's rule checks go ahead of other blocks. The queue's own `busy` task counts decide whether a block is busy; never infer that from the store's display status (`HunkState.running` is display only). Partial reviews persist, so a retry runs only the missing checks; `force` starts over. A `409` from `/check` (a rescan renamed or removed the rule) restarts the block from its overview in a new review generation; every task carries its generation, and work from an older one is skipped or its result dropped. Verdicts are derived (`reviewProgress.ts`): any failing check → fail, all applicable checked → pass. Persisted reviews are re-validated with `parseHunkReview` on load. Blocks stay `pending` while the reviewer is offline and are queued when it reports healthy. On start-up, more than 25 unreviewed blocks triggers a prompt instead of an automatic review (cost guard).
- **Reviewer service** (`src/reviewer/`) is a plain Node HTTP server, the same code in Docker and on the host. It must not import `vscode`, and it may import only from `src/reviewer` and `src/shared`, because the Docker image ships nothing else (both lint-enforced; move pure helpers into `src/shared`). Sources sent to the model go through `redactSecrets` first. Every request needs a bearer token generated per start. **All workspace reads must go through `readWorkspaceFile`** (`src/reviewer/workspace.ts`). It confines by *real* path after opening, checks that the opened handle is the same file (dev/inode), refuses non-regular files and hard links, and opens non-blocking. Never `readFile` a workspace path directly. Each overview and each rule check is a fresh, tool-less `claude -p` call (`--tools ""`, `--strict-mcp-config`, `--setting-sources ""`, cwd = a private `mkdtemp` directory deleted afterwards, `--json-schema`).
- **Prompt-injection trust boundary** (`src/reviewer/trust.ts` and `src/reviewer/prompts.ts`). This is a hard rule.
  - System prompts are static constants and must **never** contain repository-controlled text. That also keeps them byte-identical, so they stay prompt-cached.
  - Project rules, patches, file context and scan sources go in the user message through `dataBlock(nonce, …)`. Rules go through `sanitizeProjectRules` first.
  - Overviews go through `enforceOverviewPolicy` (only known rule ids, and `no-reviewer-manipulation` is always applicable). Checks go through `enforceCheckPolicy` (id and title from MALT's rule, text sanitized). `/check` takes only a rule id; the reviewer looks the rule up itself. Only the manipulation check sees the project rules; every other check sees just its own rule.
  - Discussions (`POST /architecture/discuss`) send the whole request as one data block under the static `DISCUSSION_PROMPT`, which owns the rules data can't override (context is unverified AI/repository metadata; never claim tests ran). Build dialogues with `dialogueOf` so MALT alone sets roles; replay answers with `reviewerTurn`; anything the developer said or recorded (e.g. a test result) is a developer turn, never context.
  - The baseline rule `no-reviewer-manipulation` must stay. `--bare` can't be used because it refuses subscription OAuth logins.
- **Consolidation** (`src/review/consolidation.ts`, `POST /consolidation`): one call over new declarations, complete relevant source bodies, the available full architecture map and saved standards; no declarations means no call. `reviewContext.ts` inventories eligible sources repository-wide, searches references, follows relative imports and includes callers. Coverage limits and omitted bodies are explicit; a missing or oversized primary file stops the check. Architecture, reuse, abstraction, boundary and dead-code rule checks use this component context too, while preserving one-rule isolation. Runs from `malt.checkConsolidation`, or debounced 30 s after a new-file block appears (`malt.changes.autoConsolidation`). Finding policy keeps only files whose implementations MALT supplied. Findings are not persisted. See `docs/standards.md` for budgets and limitations.
- **Shared protocol** (`src/shared/protocol.ts`): every value crossing the HTTP boundary goes through its parsers, in both directions.
- **Backends** (`src/backend/`): `ReviewerManager` prefers Docker (`DockerBackend`) when the Engine API answers and Claude credentials are in SecretStorage, and otherwise falls back to `HostBackend` (VS Code's runtime via `ELECTRON_RUN_AS_NODE`). The Docker image is built from a tar context (`tar.ts`) of `docker/Dockerfile` plus `out/reviewer` and `out/shared`, tagged with a hash of the context, so code changes rebuild it automatically. The container mounts the workspace read-only, with a read-only root filesystem, `CapDrop ALL`, `no-new-privileges`, and its port bound to 127.0.0.1 only. A health monitor polls `/health` every 10 seconds.
- **Standards scan** (`malt.scanStandards`): the reviewer reads `.claude/`, `.codex/`, `.cursor/`, Markdown docs and lint/format configs (bounded by count and size; see `standardsSources.ts`), and the model distills checkable rules. The extension writes them to `.malt/standards.json`, which is ignored by default. The reviewer re-reads it whenever its content changes. In parallel it samples the beginning, middle and end of eligible sources and the model supplies purpose, exports, what/why explanations, proposed evidence and an open question to `.malt/architecture.json`; `sanitizeModules` keeps only scanned paths. A third call (`GAPS_SYSTEM_PROMPT`) compares documented rules with the map: undocumented conventions become rules whose source MALT prefixes with `INFERRED_SOURCE_PREFIX` (never shadowing baseline or documented ids), and unsettled questions become `gaps` in `standards.json`, shown by `malt.showStandardsGaps`. All three run in one `POST /standards/scan`; a failed map or gap call becomes a warning so documented rules still save. `architecture.ts` slices it per call (name overlap with added code, then nearby folders): the initial overview gets up to 25 entries; component checks use the broader context described above, and local checks get no map. Six baseline rules always apply. A rule's `category` is its group in the Changes view; the scan prompt sorts rules into 3–8 groups and reuses the baseline ones.
- **UI**: `src/editor/decorations.ts` draws a box from per-line border decorations (top/middle/bottom/single × verdict) plus an inline status label. `reviewMarkdown.ts` builds the hover card, inserts model text only through `appendText`, and allows only the `malt.reviewAgain` command link. `detailPanel.ts` is the full-page view of a rule result or consolidation finding: a webview with scripts off, a nonce-only CSP, and every value HTML-escaped. The activity-bar container `malt` has two views, `malt.reviewer` (status) and `malt.changes` (consolidation findings, then files → blocks → rule groups → rules), and there is a status bar item.
- **Reviewer view rows** (`src/views/reviewerView.ts`): Reviewer (health and where it runs; opens the live log), Standards (opens `standardsPage`; expands into categories → rules), Gaps (expands into gaps → declarations), Architecture (opens the interactive graph in `src/architecture/explorer.ts`), Queue (only reviewing / queued / waiting / failed; reviewed blocks drop off). **No row may start a scan**: rescanning is only the title-bar `malt.scanStandards` (the show commands offer a scan only when nothing is saved). Rules, gaps and file summaries come from `StandardsModel`, which re-reads `.malt/*.json` through the protocol parsers and re-applies `enforceAnchors`.
- **Finding anchors**: gaps and consolidation findings carry `anchors` ({ file, symbol }), never line numbers from the model. `src/editor/findingHighlight.ts` confines the path with `workspaceFile`, locates the symbol via `vscode.executeDocumentSymbolProvider`, then `findDeclarationLine` (regex-escaped literal match), and outlines it with a hover that inserts text only through `appendText` (untrusted, no command links).
- **Live reviewer log**: every model call goes through `ReviewService.ask`, which records it in a `ConversationLog` (in memory, bounded, never written to disk). `GET /events` streams NDJSON (backlog, then live, plus a heartbeat) and drops a viewer that stops reading. The Claude provider uses `--output-format stream-json --verbose --include-partial-messages`, forwarding `input_json_delta` / `text_delta` text as display only; the result is still the final `result` event's `structured_output`. `src/views/conversationPanel.ts` is the only webview with scripts: strict nonce CSP, `localResourceRoots: []`, `textContent` only. Events are validated by `parseConversationEvent` before reaching it.
- **Models & effort**: `src/shared/reviewProfiles.ts` defines the four review types (overview, check, consolidation, standards), their settings keys and their defaults (cheap by design). `readSettings().profiles` validates them, `profilesToEnv` / `profilesFromEnv` carry them to the reviewer, and `claudeArgs` passes `--model` and `--effort` (no `--effort` for `default`). Model names must match `isModelName`, so nothing flag-like reaches the CLI. The tray row is `src/views/reviewSettings.ts`; changes apply on reviewer restart.
- **Workspace containment (extension side)**: any file whose path comes from data (findings, git changes, saved files) must be checked with `realRelativeInside` (`src/shared/realPath.ts`) before it is read or opened. `ChangeTracker.isReviewableFile` skips symlinks and files whose real path is outside the folder; `workspaceFile` opens the verified file at its real location relative to the real root, joined onto the workspace folder's own path, so it is the checked file but spelled as the workspace knows it (macOS `/private/var` and Windows short names would otherwise put it "outside" the workspace). Fail closed.
- **Gap investigations** (`src/reviewer/investigation.ts`, `src/shared/investigation.ts`, `src/standards/investigation*.ts`, `src/views/gapItems.ts`):
  - `POST /standards/investigate { gapId }`. The reviewer finds the gap itself by `gapId`, a content hash of title, files, note and detail. Never accept gap text from the caller.
  - `investigateGap` narrows the gap's files to architecture-mapped source files. `collectGapCode` reads, via `readWorkspaceFile` and only if `isSourceCodePath` passes, the gap files, then exporters of its anchor names, then one hop of relative imports (resolution stops at the first candidate already collected or read), all capped.
  - `enforceInvestigation` / `groundEvidence` keep only quotes found verbatim in supplied files, and mark an unsupported positive verdict low confidence. Grounding and the editor both use `findQuoteSpan` (`src/shared/quoteMatch.ts`): one whitespace-insensitive matcher, so every accepted quote is locatable. `saveInvestigation` is serialized per workspace.
  - Results are saved in `.malt/investigations.json` by gap id and pruned to current gaps. The tray shows the verdict, then a plain-English summary and evidence nodes (`malt.showEvidence` locates the quote with `findQuoteLines`).
  - Investigations are on demand only: they cost a call each.
- **Pull request review** (`src/github/githubApi.ts`, `src/pullRequest/`): `malt.reviewPullRequest` picks an open PR via the GitHub REST API (`node:https` to api.github.com only, token from `vscode.authentication` `github`: `read:user` first, `repo` only when the repository is not visible read-only and the user agrees; responses validated and capped), checks it out through the Git extension API (`fetch` `refs/pull/N/head`, `checkout` the head SHA, verify HEAD; refuse with tracked changes; finishing refuses rather than discard), and turns GitHub's per-file patches into blocks (`blocksFromFiles`: paths confined by `workspaceFile`, and the real path must be the PR path itself and a regular file, so links are skipped; capped). Starting is serialized (`starting` is set before the first await). The reviewer reads its rules and map from `.malt/` in the checkout, so `refusePolicyChanges` refuses a PR that changes anything in a `.malt` folder (case-insensitive, renames included) or lists 3,000+ files; never weaken this into a warning. The PR is re-read before checkout, `filesAtHead` re-reads the head after loading patches, and `returnOnFailure` returns to the previous branch if anything after checkout fails. `PullRequestReview` owns a separate in-memory `HunkStore`/`ReviewQueue`/consolidation and its own decorations and hovers; `commands.ts` `ownerOf` routes block commands to it, and finding commands carry a `FindingSource` (`findingsFor`). The controller watches the repository: leaving the PR's head commit or changing tracked files calls `invalidate` (`checkoutChange`), which stops the review for good, and Review All re-checks with a fresh status first. A stopped queue or consolidation drops results that land later. Finishing calls `stop()` (queue and consolidation stop scheduling and drain in-flight calls) via `returnFromPullRequest`'s `beforeLeaving`, after the dirty check and before the branch switch. Nothing is posted to GitHub. `claudePath` and `docker.socketPath` are machine-scoped so a checked-out repository can't choose what MALT runs.
- **Live log hardening**: everything logged goes through `redactSecrets` / `StreamRedactor` (`src/reviewer/redact.ts`). Never log raw prompts, streamed text or errors. **Never decode a stream chunk by chunk**: use `createLineSplitter` (`src/shared/lineSplitter.ts`, a streaming UTF-8 decoder). The page script lives in `media/liveLog.js` (lint forbids `innerHTML`, `eval` and network APIs there). It must release evicted calls and ignore messages whose `origin` is not its own `window.origin`; measured in a real webview, that is how extension messages arrive. `LiveLogConnection` owns stream lifecycle: it disconnects when the reviewer leaves `running` and reattaches to a new instance. `shutdownReviewerServer` must close all connections.
- **Auto-open must not steal attention**: auto-open goes through `AttentionGuard` (`src/editor/attention.ts`). Any user activity (keyboard or mouse selection, scrolling, switching editors) or any command that opens something (registered with `userCommand` in `commands.ts` or `register` in `standardsCommands.ts`) pauses it for `malt.changes.autoOpenPauseSeconds`. MALT's own navigation runs inside `attention.navigate` so it never counts. New "show" commands must use those helpers.

The structural map lives in `src/architecture` and uses the built-in Git API. Keep scoped snapshots and notes under `.malt/maps/v1/`. The reviewer reads `reviewer.json` for current branch context. The tracker signs it (`signMap`, Ed25519 from the note key), and the reviewer trusts it only if it verifies against `MALT_MAP_VERIFIER`, the public half passed in its environment. Its entries must name real files, and a `confirmed` counts only while the file still matches its fingerprint. Never let the reviewer accept developer intent from an unsigned file. Preserve evidence verification and the branch/path/content identity of accepted clarifications. `.malt/` is repository content, so a note counts only if its HMAC (key in SecretStorage, `loadNoteKey`) verifies; scan records never carry `confirmed`, and `sanitizeModules` sanitizes every understanding field. Never trust a note by its file name alone. `loadArchitecture` keeps committed `.malt/architecture.json` entries only for real, confined workspace files, and strips their `confirmed`. See [the explorer guide](docs/architecture-explorer.md).

## Architecture and non-obvious setup

- **Native compiler isolation.** `compile`, `check-types` and `watch` run TypeScript 7 in a Docker Linux container: no external network, read-only inputs/root, non-root UID, dropped capabilities, resource limits, and an `out/` write mount only when emitting. No host fallback. `lint` and `check-deps` retain Node permission restrictions; these are not a security boundary against malicious code. Tests, packaging, the launcher and editor run with host permissions. Read `docs/toolchain.md` before changing this boundary.
- **No npm pre/post hooks.** `ignore-scripts=true` disables them too, so scripts chain steps explicitly (for example `test` runs `npm run compile && …`).
- **Two TS projects.** `tsconfig.base.json` holds the strict compiler flags. `tsconfig.json` builds `src/` → `out/` as CommonJS, with `verbatimModuleSyntax: false` because VS Code loads CJS and `erasableSyntaxOnly` forbids `import x = require()`. `scripts/tsconfig.json` type-checks `scripts/*.mts` with noEmit. Those scripts are run directly by Node 24's type stripping, so they must use erasable syntax only.
- **Tests.** `src/test/runTest.ts` calls `@vscode/test-electron`, which loads `out/test/suite/index.js` in the extension host. Each `*.test.ts` exports `tests: TestCase[]` (from `src/test/suite/harness.ts`) and uses `node:assert/strict`. `node:test` hangs in the extension host, so don't switch to it. `--disable-extensions` only disables *other* extensions; MALT is loaded through `--extensionDevelopmentPath`.
- **Packaging.** `.vscodeignore` is an allowlist (`**` then re-includes). It re-includes each `out/<folder>/**/*.js` explicitly, because vsce lets a `!` re-include beat a later exclude, so `out/test` can't be carved out of a broad `!out/**`. It also ships `media/` and `docker/Dockerfile`, which the Docker backend needs at runtime. **A new top-level folder under `src/` must be added there**, or it won't ship. `vsce` runs with `--no-dependencies`.
- **Artwork** lives in `design/` (hand-written SVG and HTML/CSS sources plus their PNG exports; not shipped), with shipped assets under `media/` and documentation images under `docs/images/`. The README uses PNGs because vsce rejects SVG images there. Never use an image generator for project art. The mark's shape comes from `media/malt.svg`; `design/brand/mark.svg` and the lockups reuse its paths. Diagrams must match real behavior, so update `design/pipeline.html` or `design/trust.html` with the change they depict. See `docs/design.md`.
- **Docker image pins.** `docker/Dockerfile` pins `node:24-slim` by digest and `@anthropic-ai/claude-code` to an exact version. Bump both deliberately. They live inside the image, not in `package.json`, so `check-deps` doesn't cover them.
- **Releases** (`release.yml`, `scripts/release.mts`): a signed, annotated `vX.Y.Z` tag on a `main` merge commit runs `ci.yml` and `reviewer-live.yml` (via `workflow_call`; the live test makes real Claude calls of every kind, so a reviewer the API rejects can't ship), rebuilds the `.vsix`, requires its `out/` to be byte-identical to CI's, attests provenance and creates a draft release that a maintainer publishes. The version lives in `package.json`, both `package-lock.json` fields and a dated `CHANGELOG.md` section; change them only with `npm run release:bump` (plain `npm version` rewrites the whole `package.json`). Keep the workflow's write permissions in the publish job only.
- **CI** (`.github/workflows/`) uses only `actions/*` and `github/*` actions, pinned to full commit SHAs. Keep that pattern when updating (the repository's Actions policy also enforces it). `branch-policy.yml` uses `pull_request_target` so a PR can't edit its own check; it must never check out or run PR code. `discord-shipped.yml` (also `pull_request_target`) posts merged PRs and releases to Discord with a secret from the `discord` environment: never check out PR code there, keep `permissions: {}`, and keep untrusted text neutralized (invisible characters stripped, secrets redacted, inline code, empty `allowed_mentions`, length cap), add no concurrency group (it would drop pending posts), and keep the file ASCII only (YAML reads U+2028/U+2029 as line breaks).
- **Branches.** `dev` is the default branch and the only PR target; `main` accepts PRs from `dev` only (the *Source branch is dev* check). Branch from `dev`, never push to `dev` or `main`, and open PRs against `dev`. Every commit in a PR must be signed (the gates can't be bypassed); this clone signs with an SSH key via local git config, so never pass `--no-gpg-sign` or `-c commit.gpgsign=false`. Rulesets, required checks and every other repository setting are recorded in `docs/repository-settings.md`; when you change a check's job name or add a required workflow, update the rulesets and that doc together.

## Environment

Windows 10 dev machine. The repo path contains spaces, so quote paths. npm scripts run under cmd.exe locally and sh in CI, so keep script syntax portable (`--allow-fs-read=\"*\"` is quoted so sh doesn't glob it).
